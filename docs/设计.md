# AI 助手模块设计

## 需求

本模块为 CopperGolem 提供面向用户的 AI 助手，首期覆盖通用问答与启动器问题诊断。模块基于开源项目 [Pi](https://github.com/earendil-works/pi) 的 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai`，复用其 Agent 对话循环、工具调用、流式事件及多 provider 模型接入能力；不嵌入完整 Pi Coding Agent CLI/TUI，也不自建模型调用、Agent 循环、会话协议等基础设施。

本模块负责：

- 提供符合 CopperGolem 主题令牌和 i18n 约定的聊天 UI，呈现流式文本、工具调用状态、错误与取消反馈。页面结构为：顶部会话栏（历史下拉、当前会话名、新建与设置图标按钮）、中部对话流、底部输入栏，详见「对话流前端设计」。
- 注入少量 CopperGolem 专属提示词，使助手能区分通用问答与启动器问题诊断，并对不确定的信息如实说明。
- 定义 CopperGolem 专用 MCP 工具接口，后续按最小权限提供所需上下文和操作。工具清单、参数、数据来源、权限与阻塞项见[MCP 工具设计](MCP工具设计.md)。
- 在启动器设置中提供 provider、模型和 API 地址等配置入口。API Key 只存内核安全存储，由内核下发给它监管的 Node 会话，不得写入普通设置、模块存储、会话记录或日志。Agent 的能力边界、工作区与授权方式见[安全设计](安全设计.md)。
- 复用 Pi 的会话和消息能力，并**持久化会话**：会话列表、标题与消息内容需可跨重启恢复，历史下拉由此驱动。
- 输入栏接入 Pi 原生命令与权限逻辑：`/` 调用 Pi 实际暴露的命令列表，权限批准按 Pi 的权限模式实现，不自行编造命令表或审批语义。

首期不包含：代码仓库写入、任意命令执行、开放式文件系统访问、完整 Pi Coding Agent 功能或另建一套 Agent 框架。

## 架构

### 组件职责

1. **聊天前端**：Vue 页面负责会话交互和展示，不直接承担 Agent 循环。所有用户文案经模块 i18n，样式只使用 CopperCore 主题令牌，图标使用 `@lucide/vue`。
2. **Pi Agent 适配层**：运行在宿主监管的 Node 会话内，使用 Pi Agent Core 创建和管理 Agent，将 Pi 的流式事件转换为模块可消费的事件；转发提示词、取消信号和工具执行状态。适配层只处理 CopperGolem 集成，不复制 Pi 的会话/Agent 机制。
3. **Pi AI 模型层**：同样运行在 Node 会话内，使用 Pi AI 及其原生 provider 完成模型调用。设置 UI 的 provider/model 配置映射到 Pi 支持的配置接口；API Key 由宿主从内核安全存储取出后仅下发给该 Node 会话，不进入前端持久化状态、模块存储与日志。
4. **CopperGolem MCP 工具**：单独定义工具及其 schema、输入校验、权限边界和结果格式。由于 Pi Agent Core 本身不等于 MCP 客户端，集成层需提供薄适配，使已批准的 MCP 工具可作为 Pi Agent 工具被调用；不额外实现通用 MCP 平台或 Agent 工具框架。
5. **内核受监管 Node 运行时**：由铜内核定位并校验系统 Node、派生并监管模块专属 Node 会话、下发凭证与代理解析设置、转达模块请求与流式事件、执行超时/取消/回收。详见「运行时与进程模型」。
6. **内核模块接入**：按模块契约接入生命周期、命令、事件、设置/i18n 与数据持久化。模块间访问通过内核已经提供的 API/意图契约，不直接依赖其它模块内部实现。

### 数据流

用户提交消息 → 前端调用模块 API → Pi Agent Core 接收 prompt → Pi AI 调用选定 provider/model → Agent Core 通过事件持续返回回答或工具调用状态 → 前端更新会话视图。若模型请求调用 CopperGolem 工具，Pi 适配层仅调度已注册、经 schema 校验的 MCP 工具，并将结果返回 Agent Core 继续生成。用户取消时，取消信号应到达正在进行的 Pi 请求，并尽可能停止当前工具调用；取消与工具副作用之间的语义需按具体工具定义。

实际链路为：前端调用模块命令 → 模块 Rust 后端经内核受控能力转达 → 内核把请求交给它监管的 Node 会话 → Pi Agent Core 驱动 Pi AI 发起模型请求。流式增量、工具状态与结束事件沿原路回传为模块事件，前端据此更新会话视图。

设置只保存 provider/model 等非敏感选项；API Key 单独存内核安全存储，运行时才下发给宿主监管的 Node 会话。会话数据只保存必要的用户消息、回答与工具结果，不保存 API Key、认证头或未经筛选的敏感诊断信息。

### 对话流前端设计

页面自上而下分为三段：顶部会话栏、中部对话流、底部输入栏。对话流是主体，不设常驻侧栏，历史会话经顶部下拉进入。

**顶部会话栏**

- 左侧为历史入口：图标按钮展开会话浮层，列出往期会话（标题、时间），支持搜索、切换与删除，当前项高亮；空列表显示占位文案。历史数据来自持久化会话库。
- 中部为当前会话名称，过长省略号截断。
- 右侧为「新建会话」与「设置」两个图标按钮。新建会开启空会话，若存在生成中任务先停止。设置面板放置 provider、模型、API 地址与 API Key；Key 使用密码输入框，不回显已保存明文，提供保存、替换与删除。

**对话流**

- 用户消息：头像加无描边圆角气泡，靠右显示。
- 助手消息不使用气泡，通栏渲染，且分为两种形态：
  - 生成中：实时展开任务时间线，顶部显示进行中状态行（当前动作与已完成步数）。
  - 完成后：任务时间线自动折叠为一行摘要 `任务过程 · <耗时>`，下方完整展示最终回答（Markdown 正文）。
- 任务时间线按真实时序交错排布以下元素，工具区左侧以一条细线贯穿并承载图标：
  - 任务摘要行：`任务过程 · <耗时>`，整行点击折叠/展开。
  - 章节行：`参考内容`、`思考过程`，带折叠指示；Pi 未提供推理内容时不显示「思考过程」。
  - 工具聚合行：连续同类调用合并为一行的数量摘要，可展开子项；中间插入推理文本时断开分组，单一调用直接显示单项行。
  - 工具单项行：图标加动作描述（如「已读取 main.ts」），悬浮显示完整参数；失败项用警示色并可展开错误。
  - 工具结果行：缩进子行（如「找到 15 行 "scripts"」），无结果时显示「未找到结果」。
  - 推理文本：通栏纯文本段落，与工具行按真实时序交错，无图标无气泡。
- 最终回答底部提供三个图标操作，仅在回答完成后出现：复制最终回答、分享（首期保留按钮位并提示即将支持，生成图片功能后续实现）、重新发送本轮用户提示词。重新发送会停止进行中的生成并在末尾追加新一轮。
- 层级用字色与缩进表达：章节行与聚合行用次要色小字号，正文用主文本色；不使用气泡与卡片堆叠。

**底部输入栏**

- 固定于底部，宽度居中并设最大宽度；多行输入，Enter 发送、Shift+Enter 换行。
- 左下角为 `/` 命令入口与权限模式入口。输入 `/` 弹出命令列表并随输入过滤，上下键选择、Enter 执行、Esc 关闭；命令清单取自 Pi 实际暴露的命令，不硬编码。权限模式用于切换自动执行与手动审批，具体粒度以 Pi 权限能力为准；某次工具调用需要批准时，在时间线内插入审批行并提供允许/拒绝。
- 右下角为模型选择与发送按钮；模型未配置时提示前往设置；生成中发送按钮切换为停止。

**交互与状态**

- 生成中自动吸底；用户上滚时暂停跟随并浮出「回到最新」，滚回底部恢复。
- 用户手动展开的章节在本会话内保持展开状态，切换会话不串。
- 失败步骤保留可展开的错误信息；取消后时间线冻结并在末尾追加「已取消」，允许重新发送。
- 流式追加需平滑且不引起折叠态跳动；小窗口下模型标签收缩、操作按钮换行，不出现横向溢出。
- 需覆盖状态：未配置 API Key、模型不可用、网络错误、限流、取消中、权限待批准、`/` 无匹配结果、历史为空。

**持久化模型**

会话落库保存结构化块序列，而非拼接的纯文本，否则重开历史无法还原任务时间线。每条助手消息存储：块类型（章节、工具聚合、工具项、结果、文本）、工具名与参数摘要、状态、耗时，以及最终回答正文。切换会话时按块序列重建视图；写入前过滤工具参数中的敏感值。

### 运行时与进程模型

Pi SDK 是 TypeScript/JavaScript 包，不能作为 Rust 依赖直接调用；模块骨架的 Vue 前端也不得持有密钥。进程模型已定案如下，实现必须遵循，不得改写为“Rust 直接调用 Pi SDK”或“WebView 持有密钥”。

- **承载方式**：铜内核派生并监管一条**模块专属的 Node 会话**，在其中运行固定版本的 Pi Agent Core 与 Pi AI。模块自身不启动 Node，也不申请或使用 `process:spawn`。
- **Node 来源**：使用用户系统已安装的 Node，不随模块或内核分发、不自动下载。启动前校验版本必须 `>=22.19.0`：`@earendil-works/pi-agent-core`、`@earendil-works/pi-ai` 与 Node SQLite 会话后端在 v0.87.1 的 `engines` 中均声明该下限，因此不能按更低版本承诺兼容。不满足时给出可操作的安装/升级提示并拒绝启动，不做静默降级；允许用户在设置中显式指定 Node 路径，仍须通过同一版本校验。
- **入口与参数**：Node 可执行路径、runtime 入口脚本与启动参数全部由内核固定，模块不能传入或替换；入口脚本位于模块目录内，装载与启动前按沙箱路径规则校验其归属。
- **通信**：内核与该 Node 会话之间使用有界、版本化的私有 IPC（请求/响应 + 单向流式通知）。stdout 专用于协议，stderr 限长保留并在脱敏后仅用于诊断。模块的 Rust 后端**不与该会话直连**，只通过内核新增的受控能力转达请求，因此凭证通道不经过模块插件。
- **生命周期**：会话随模块 `start` 建立、`stop` 回收；具备握手版本协商、逐次调用超时、取消、进程树终止与退出兜底，避免孤儿进程。
- **凭证**：API Key 只存内核安全存储，会话建立起后由内核按需下发给它监管的这一条 Node 会话。不下发给模块插件，不进入模块存储、普通设置、前端持久化、会话库、日志与工具输出。**Node 进程内存中会存在密钥，这是本方案的已知信任支出。**
- **网络**：模块按收录口径声明 `network` 权限，内核以该权限门禁 agent 能力并在每次调用时经沙箱逐次校验（复用现有 `Permission::Network`，首期不新增权限枚举）。模型请求由 Pi 原生 provider 自行发起；内核负责把解析出的系统代理设置注入 Node 会话，以满足“网络请求走系统代理”的项目约束。
- **不承诺的能力**：首版不实现操作系统级网络出口隔离，也不校验用户的 Node 二进制未被替换。因此“密钥永不离开进程”与“模块无法对外直连”均不作为保证；只承诺密钥不进入模块可读通道与任何持久化通道。Android 首期不支持，明确报错而不回退。

实现前必须完成的前置验证：

- Node 版本探测、路径来源优先级与缺失/过低时的提示文案。
- IPC 帧上限、逐次超时、取消传播与进程树回收在真实进程上可用。
- 系统代理解析设置注入后，Pi AI 经 `http-proxy-agent` / `https-proxy-agent` 实际生效。
- 凭证下发通道确认不经过模块插件，且日志/错误路径无密钥回显。
- vendor 依赖锁定、许可证与来源核对方式。

## 备注

- 上游 Pi 项目是 npm monorepo，含多个包。本模块以 `earendil-works/pi` 的稳定 tag `v0.87.1` 为底座，只保留 Agent Core、Pi AI 及其构建与运行所必需的传递依赖，不打包完整 Pi CLI/TUI；裁剪必须按锁定的依赖图进行，而不是只复制两个目录。上游升级应审查 API 兼容、依赖变化与许可证，并重新锁定经过验证的版本。
- Pi Agent Core 提供 Agent 和工具执行流程，但不能据此推断其原生支持 MCP；MCP 工具到 Agent 工具的适配是本模块的集成责任。MCP server 与宿主/Agent 的传输方式、启动方式及权限授权，需结合内核实际支持的运行时契约另行确认。
- 工具应遵循最小权限和最小数据原则。首期只读工具清单已定稿，见[MCP 工具设计](MCP工具设计.md)；任何后续有副作用的工具都需明确用户确认、可取消性和失败反馈。
- 当前 cgl-agent 仓库仍是示例附加模块骨架，`module.json` 还是模板的 `copper-lamp.demo-tools`，需改为 `copper-lamp.agent`、`i18n_namespace` 改为 `agent`。按内核当前源码，附加模块的受管控 helper 子进程（`registry/helper_backend.rs`）与能力派发（`registry/capability.rs`）已有实现，能力表当前开放 `module.info`、模块私有 `storage.*`、`intent.request`（需 `intents` 权限）与 `events.publish`（需 `events` 权限且受清单发布上界约束）；文件、网络、设置、数据库、凭证与进程均不可达。因此 agent 会话能力必须由内核新增，日志读取与联网两项工具同样依赖内核新增受控接口，见[MCP 工具设计](MCP工具设计.md)的阻塞项。
- 该设计已确定技术方向、职责边界、对话流前端方案、只读工具集合与运行时/凭证/网络三项进程模型决策（见「运行时与进程模型」），会话持久化已确认为必需。剩余待办是内核侧 agent 会话能力与受监管 Node runtime 的实现、vendor 落地与日志/联网两项工具的接口设计。不得用假实现绕过这些决策。分享生成的图片功能已明确推迟，首期只保留按钮位与提示。
- 前端已按「对话流前端设计」整篇落地（2026-09，`frontend/src/`）。页面结构：`ModulePage.vue` 组合 `agent/` 下的 `SessionBar`（历史入口、当前会话名、新建/设置）、`ConversationStream`（消息流 + 生成中自动吸底 + 上滚浮出「回到最新」）、`Composer`（多行输入、Enter 发送 / Shift+Enter 换行、`/` 命令入口、权限模式、模型、发送切换停止）、`SessionHistoryPanel`（搜索、切换、删除、空态、当前项高亮）、`SettingsPanel`（provider / 模型 / API 地址 / API Key，密码输入且不回显已保存明文，提供保存、替换、删除）、`CommandPalette`（上下键选择、Enter 执行、Esc 关闭、无匹配态）。消息形态：用户消息为头像 + 无描边气泡靠右；助手消息通栏无气泡，生成中显示进行中状态行（当前动作 + 已完成步数）并实时展开时间线，完成后折叠为 `任务过程 · 耗时` 摘要行，下方为 Markdown 正文与复制 / 分享 / 重新发送三个操作。任务时间线由 `TaskTimeline.vue` 渲染章节行（参考内容、思考过程）、推理文本、工具聚合行、工具单项行、工具结果行与审批行，工具区左侧细线贯穿并承载图标，折叠态按会话隔离。样式集中在 `styles/module.css`，只消费 `var(--copper-*)` 令牌；助手正文经 `marked` + `DOMPurify` 白名单净化后插入（与内核内容模块同一安全口径，依赖已加入 `package.json`）。
- 前端与后端的边界在于「真实发出、如实失败」：`agent/backend.ts` 单点声明模块自身命令名（`agent_session_prompt` / `agent_session_cancel` / `agent_sessions_list` / `agent_session_load` / `agent_session_delete` / `agent_commands_list` / `agent_approval_respond` / `agent_settings_save` / `agent_credential_clear`）并把所有结果归一化为 `{ok, data}` 或可展示的 `Failure`；`agent/useAgentChat.ts` 承载会话、发送、停止、重发、审批、设置的交互。内核 Agent 会话能力尚未接入时，请求会真实发出并失败，界面据此显示「Agent 会话能力未接入」并提示本次请求已丢弃，绝不本地伪造回答或保存成功；取消信号即使未送达，界面也只冻结本轮并追加「已取消」，同时如实提示信号未送达。`capabilities` 中的 `sessionBackendAvailable` 为 false 时页面顶部显示未接入横幅，`persistenceUnavailable` 为 true 时说明关闭页面后对话不保留，`credentialStorageUnsupported` 为 true 时禁用 Key 相关操作，对应「需覆盖状态」。
- 入口与预览：`register.ts` 在求值阶段经 `host.ts` 的 `captureHostBridge()` 抓住 `window.__COPPER_HOST__`（内核在动态导入后会立即清空该全局，界面渲染后再取就没了），经它登记 `/agent`，不再静态导入内核注册表；`dev-preview-kernel.ts` 为 `npm run dev` 提供等价最小桥与 i18n 桩，且必须在 `register.ts` 之前以副作用形式求值（ES 模块导入按源码顺序执行，写成普通语句会被提升挤后导致路由登记时桥不存在）。
